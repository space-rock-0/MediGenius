01 / About

Health questions need context and restraint.

The assistant turns health information into plain language while keeping high risk decisions with qualified people.

For people asking health questions

Understand a condition, organize symptoms before a visit, or learn general medication information.

For a safer boundary

Crisis language and selected dosing or interaction topics trigger fixed referrals before model generation.

Grounded context

A local medical PDF, Wikipedia, and Tavily can supply context for relevant questions.

Conversation continuity

SQLite history and session scoped semantic recall support follow-up questions.

02 / Capabilities

Built around the answer.

These are implemented paths in the current repository. Open a card for the behavior behind it.

✚

Safety routing

Pattern checks handle crisis and emergency language before retrieval or LLM calls.

How it works

A blocked query receives a fixed response. Pediatric or pregnancy dosing, and drug interaction requests, use refusal or referral paths.

↗

Parallel retrieval

The active graph fans medical PDF retrieval, Wikipedia, and Tavily out concurrently.

How it works

Successful sources are prioritized: curated PDF, then live web, then encyclopedia. Failed branches can fall back to the direct LLM path.

◇

Answer verification

A diagnosis verification sub-agent checks generated claims and can hold back high risk output.

How it works

Post-processing also removes dosage figures that are not found in retrieved source text.

◎

Session memory

Conversation history persists in SQLite, with semantic recall in a separate Chroma collection.

How it works

Users can start, load, clear in-memory state, and delete sessions. Session deletion also removes semantic memory entries.

≋

Streaming progress

The chat stream emits named stage events before its final answer payload.

How it works

The React UI consumes /api/v1/chat/stream and shows progress labels while the pipeline runs.

□

Review queue

Metadata flags safety, refused, fallback, or high risk answers for a paginated review queue.

How it works

A review verdict is stored alongside the original audit row. The API also exposes aggregate counts and agreement rate.

07 / Getting started

Run the application.

README instructions require Python 3.10+, Node.js 18+, and Groq and Tavily API keys.

1. Configure

Create backend/.env with the documented required keys. The additional settings below have defaults in core/config.py.

backend/.env
GROQ_API_KEY=your_key_here
TAVILY_API_KEY=your_key_here

2. Start locally

The README recommends the root helper, which starts both backend and frontend.

terminal
python run.py

Frontend: localhost:5173 · Backend: localhost:8000 · FastAPI docs: localhost:8000/docs

Manual development

Run these in separate terminals.

backend
cd backend
python -m uvicorn app.main:app --reload
frontend
cd frontend
npm install
npm run dev

Container run

The repository also includes a Docker Compose setup.

terminal
docker-compose up --build

The page you are viewing is standalone and does not need the app server to render.

08 / Security & limits

Know the boundary.

The repository describes an information assistant. The current API has no user authentication or authorization.

Safety before generation

Pattern-based crisis detection and topic refusals run before model invocation. The pattern approach can miss language outside its rules.

Validation & rate limits

Pydantic validates request models. SlowAPI applies a configurable limit to chat, stream, and review submission routes.

Data handling

SQLite stores full conversation messages. Audit rows record metadata without raw question or answer text. Chroma holds document vectors and session memory.

Current deployment consideration: review and session APIs are unauthenticated; the README states that authentication is required before real user deployment. The CORS middleware currently allows all origins. This guide does not imply clinical validation or diagnosis capability.
